# Roadmap

Last verified: 2026-11-07

Atlas is in active development. Life Phase 1 is **CLOSED WITH DOCUMENTED LIMITATIONS**. The final matrix below maps all 104 audited requirements to implementation evidence, explicit limitations, and phase disposition.

## Completed

| Area | Delivered functionality |
| --- | --- |
| Application shell | Routed React application, sidebar navigation, responsive dashboard layout |
| Dashboard | Daily focus view and core signals across Focus, Health, Journal, and Streaks; neutral local visit streak; secondary modules remain available through navigation |
| Focus | Add, complete, remove, and persist focus items |
| Health | Edit and persist weight, water, sleep, and workout metrics |
| Journal | Create, search, delete, and persist entries with mood and energy fields |
| Streaks | Create and remove habits; record daily completion; configure weekday rest days; show a labeled seven-day status and calculate current/best streaks over scheduled days. Schedule edits apply to recorded history, so adding a rest weekday can bridge prior completions across that weekday. |
| Savings | Record and remove income, expense, and savings entries; calculate a running balance |
| Goals | Add, manually complete, and remove outcomes; optionally add and reorder up to five milestones on a calm, accessible roadmap |
| Notes | Add and remove personal notes; surface the latest note |
| Settings | Select a startup page, export/import the SQLite data store, and reset all local data |
| Local persistence | SQLite compiled to WebAssembly, saved in IndexedDB for Focus, Health, Journal, Streaks, and Savings |
| Unified data management | Goals, Notes, and the startup preference now use the same SQLite-backed data store, with automatic migration from their previous `localStorage` keys |
| Backup and reset coverage | SQLite backup includes every module and the startup preference; reset clears every module and restores the default startup page |
| Offline initialization | The SQLite WebAssembly asset is bundled with the application rather than fetched from a CDN |
| Persistence verification | Automated tests cover database export/import and failed-import data preservation |

### Part 9 / Part 15 conflict resolution

Part 9 places progress indicators, development gaps, attention areas, progress history, strongest/neglected dimensions, recent improvements, stagnant areas, achievements, and suggested priorities under its Phase 1 dashboard heading. Part 15 separately assigns current-versus-target comparisons, progress tracking, historical charts, milestones, and achievements to Phase 2, and assigns Life Intelligence, neglected/stagnant detection, historical comparisons, monthly reviews, and suggested actions to Phase 3. These directions cannot all be satisfied in Phase 1 without violating the later roadmap or making unsupported judgments.

Implemented Phase 1 reconciliation: show factual profile, current observations, targets, recorded dates, Health/Savings/Journal snapshots, and non-scored dimension coverage. Deterministic comparisons/charts and milestone workflows remain Phase 2; interpreted insights, neglect/stagnation detection, and suggestions remain Phase 3. Missing data stays distinct from poor outcomes. "Strongest dimensions" remains excluded because the source defines no safe objective criterion. This does not authorize Phase 2 or Phase 3 implementation.

Part 11's weekly/monthly/annual cadence is not assigned a phase. Implemented resolution: Part 11 reviews are optional user-authored records in Phase 1; Part 15 Phase 3 monthly reviews are interpreted/data-driven reviews. An authored multi-year reflection is Phase 1, while computed multi-year comparison is Phase 2 and interpretation remains Phase 3. Daily Journal and measurement flows remain the daily record; no duplicate generic daily review was added. Multi-year comparisons map most directly to Part 15 Phase 2 historical comparisons, but remain an explicit cross-reference rather than an implicit completion.

### Finalization decisions and remaining limitations

The owner approved these final product policies: the 35 built-ins are an optional starter catalogue, custom attributes provide meaningful coverage across every dimension, net worth may be a user-reported estimate, income remains explicitly scoped, and learning/travel values may be represented by user-defined attributes. Itemized assets/liabilities and specialized learning/travel systems are not required for Phase 1. No further product decision is open.

Non-blocking limitations are recorded in the final matrix: the Life dashboard shows the available Health snapshot metrics rather than every possible physical statistic; it does not aggregate Streaks into a Life summary; activity/milestone associations and milestone workflows are deferred to Phase 2; the “strongest dimensions” ranking is intentionally not implemented because no non-judgmental definition exists; application-level encryption is not present; and a genuine Narrator speech-output check could not be completed because this environment exposes no way to hear or capture Narrator speech. Keyboard, accessibility-tree, reduced-motion, and responsive checks are separate evidence and are not represented as screen-reader testing.

Part 9 vs Part 15 is resolved as follows: Phase 1 is factual current information, authored targets/reflections, identity and source-feature snapshots; Phase 2 owns activity mappings, milestone workflows, current/target comparisons, and charts; Phase 3 owns interpreted insights, neglect/stagnation analysis, and suggested priorities. A requested strongest-dimension judgment is not assigned to a later phase and remains explicitly not satisfied under the product's no-ranking principle.
