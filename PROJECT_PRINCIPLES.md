# Project Principles

# Atlas

> **Reduce the friction between who you are today and who you want to become.**

---

# Why Atlas Exists

Modern productivity software has become overwhelming.

Dashboards become cluttered.

Habit trackers become games.

Task managers become endless lists.

Instead of helping people think clearly, many applications create another system that needs managing.

Atlas exists to solve a different problem.

It aims to become a calm, intentional personal operating system that surfaces only what truly matters.

The goal is not to maximize productivity.

The goal is to help users make better daily decisions.

---

# The North Star

Every feature should answer one question:

> **Does this reduce mental friction?**

If the answer is no, the feature probably does not belong in Atlas.

---

# Core Values

## 1. Clarity Over Complexity

Information should be obvious.

Interfaces should feel effortless.

Complexity belongs in the implementation—not in the user experience.

---

## 2. Focus Over Volume

More information is rarely better.

Atlas should help users identify what matters today instead of displaying everything at once.

---

## 3. Consistency Over Perfection

Small improvements repeated consistently are more valuable than occasional bursts of motivation.

Atlas should encourage sustainable habits rather than unrealistic expectations.

---

## 4. Calm Over Noise

No unnecessary animations.

No flashy dashboards.

No distracting notifications.

No visual clutter.

Atlas should feel quiet.

---

## 5. Ownership

The user's data belongs to the user.

Atlas should work locally whenever possible.

Cloud features should always remain optional.

---

# Design Philosophy

Every screen should answer a single question.

Examples:

Dashboard

"What matters today?"

Health

"How am I doing?"

Journal

"What happened today?"

Settings

"How can Atlas work better for me?"

Avoid mixing multiple responsibilities into one screen.

---

# Engineering Philosophy

Good software is easier to maintain than to create.

Prefer:

- Simplicity
- Readability
- Explicitness

Avoid:

- Clever code
- Premature optimization
- Large abstractions

---

# User Experience Principles

Atlas should feel:

- Calm
- Fast
- Predictable
- Intentional
- Trustworthy

The interface should disappear so the user can focus on their life.

---

# Decision Framework

Before implementing any feature, ask:

1. Does it reduce friction?
2. Does it improve clarity?
3. Is it simple?
4. Will users benefit every day?
5. Does it fit the philosophy?

If the answer is "no" to most of these questions, reconsider the feature.

---

# What Atlas Is Not

Atlas is not trying to become:

- Notion
- Obsidian
- Todoist
- ClickUp
- TickTick
- Trello

Those are excellent products.

Atlas has different goals.

It values intentional simplicity over feature completeness.

---

# Long-Term Vision

Atlas should eventually become the first application a user opens in the morning and the last one they close at night.

Not because it demands attention—

because it provides clarity.

---

# Final Principle

Every feature should make the application feel lighter—not heavier.

Every line of code should exist for a reason.

Every design decision should serve the user.
